Spring6 课程知识分章总结

跟着 B 站尚硅谷的 Spring6 全套课程学习（课程地址，共 88 集约 15 小时，源码级讲解）。这篇文章把课程知识按章节整理：第一节是学习路线，后面每一节对应课程的一章。每章末尾附对应的视频分 P。

第一节：学习路线

  • 基础篇（P2–10）：Spring 概述、入门案例、整合 Log4j2 日志
  • 核心篇（P11–60）：IoC 容器（XML + 注解）、手写 IoC 原理、AOP 面向切面
  • 整合篇（P61–87）：JUnit、JdbcTemplate、声明式事务、Resources、国际化、数据校验、AOT

我的进度：P1–P64 已完成，从声明式事务（P65）继续往后学。

第二节：基础篇

2.1 Spring 概述

  • Spring 是什么：一款主流的 Java EE 轻量级开源框架，广义上是 Spring 全家桶生态，狭义上指 Spring Framework（IoC + AOP 的容器框架）。
  • 核心特点：非侵入式（不依赖框架 API）、控制反转 IoC、面向切面 AOP、一站式整合各种框架。
  • 模块组成：Core Container（core/beans/context/spEL）是地基，其上是 AOP/Aspects、Data Access（jdbc/orm/tx）、Web、Test 等模块。
  • **Spring6 要求 JDK 17+**（课程配套：Spring 6.0.x + JDK17 + IDEA + Maven）。

视频：P2–P5

2.2 入门案例

程序分析：底层就是反射（Class.forName + 构造器）创建对象；我们不再 new，创建权交给了容器 —— 这就是控制反转的初体验。

视频：P6–P8

2.3 整合 Log4j2 日志框架

  • 引入 spring-boot-starter-log4j2（或 log4j2-core + log4j2-slf4j2-impl），排除默认的 spring-jcl 依赖。
  • log4j2.xml 配置：Configuration > Appenders（Console/File/RollingFile）> Loggers，日志级别 trace < debug < info < warn < error < fatal。

视频：P9–P10

第三节：IoC 容器（核心一）

3.1 IoC 与 DI 概念

  • 控制反转 IoC：对象的创建权由程序反转给容器，降低耦合。
  • 依赖注入 DI：IoC 的实现方式 —— 容器在创建 bean 时自动给它的属性赋值（IoC 是思想，DI 是手段）。
  • 两种实现：BeanFactory（基础，懒加载）与 ApplicationContext（超集，启动即加载、事件/国际化等企业功能）。常用实现类：ClassPathXmlApplicationContext、FileSystemXmlApplicationContext、AnnotationConfigApplicationContext。

视频：P11–P13

3.2 基于 XML 管理 Bean（13 个实验）

# 实验 关键点
一 获取 bean getBean(id) / getBean(类型)；同一个 bean 默认单例
二 setter 注入 <property name="..." value/ref="..."/> 调用 setter
三 构造器注入 <constructor-arg name/index value ref/>；重载按参数匹配
四 特殊值 null 用 <null/>；XML 特殊字符用 <![CDATA[>]]>；实体字符 &gt;
五 对象属性 引用外部 bean ref；内部 bean（匿名、外部拿不到）；级联赋值
六 数组属性 <array><value>
七 集合属性 <list> <map><entry key value/> <set>；util:list 定义独立集合 bean 再引用
八 p 命名空间 xmlns:p，p:xxx="值" p:xxx-ref="ref" 简化 setter 注入
九 引入外部文件 xmlns:context + <context:property-placeholder> + ${jdbc.url}（典型：数据库配置）
十 作用域 scope="singleton"（默认，容器启动即创建一份）/ "prototype"（每次 getBean 新建）
十一 生命周期 实例化 → 属性注入 → BeanPostProcessor 前置 → 初始化方法（init-method / @PostConstruct）→ 后置 → 使用 → 销毁（destroy-method / @PreDestroy，仅单例由容器管理）
十二 FactoryBean 实现 getObject()/getObjectType()/isSingleton()，容器里放的是工厂产出的对象
十三 自动装配 autowire="byType"（唯一类型匹配）/ "byName"（id 与属性名一致）；XML 自动装配不常用，注解才是主角

视频：P14–P37

3.3 基于注解管理 Bean

  • 开启组件扫描：<context:component-scan base-package="com.atguigu"/>。
  • 标识组件：@Component 通用，语义化衍生 @Service（业务层）、@Repository（持久层）、@Controller（控制层）；value 即 bean id，默认类名首字母小写。
注入方式 匹配逻辑 备注
@Autowired 先 byType，多个同类型再 byName Spring 提供；找不到配合 @Qualifier("xxx")；@Primary 优先
@Resource 先 byName，找不到再 byType JDK 标准（Jakarta）扩展包
普通属性 @Value("...") 结合 ${} 读外部配置
  • 全注解开发：@Configuration + @ComponentScan 取代 XML，用 AnnotationConfigApplicationContext(配置类.class) 启动。

视频：P38–P43

第四节：手写 IoC（原理）

  • 回顾反射：Class.forName 三种获取方式、getDeclaredConstructor().newInstance()、私有成员 setAccessible(true)、注解的读取（isAnnotationPresent / getAnnotation）。
  • 模拟实现：自定义 @MyComponent + @MyDi，扫描包下所有 class → 有注解的反射实例化放入 Map<类名, 对象> → 遍历字段，带 @MyDi 的反射注入。
  • 收获：真正理解”容器 = 反射 + 注解 + Map”，@Autowired 本质也是这套流程。

视频：P44–P51

第五节：AOP 面向切面（核心二）

  • 场景：计算器每个方法都要日志、异常处理 —— 代码重复 → 引出代理。
  • 静态代理：写一个代理类包一层，接口一变两边都改，繁琐。
  • 动态代理（JDK）：Proxy.newProxyInstance(类加载器, 接口数组, InvocationHandler)，运行时生成代理类，无侵入地加日志/异常。
  • 术语：横切关注点、连接点（哪些方法）、切入点（实际被增强的方法，表达式定位）、通知（增强逻辑）、切面（切入点 + 通知）。

基于注解的 AOP（AspectJ 表达式：execution(修饰符 返回类型 包.类.方法(参数))）：

  • 环绕通知最万能，等价于前四种的组合；@After 无论正常/异常都执行。
  • 也有基于 XML 的 AOP：<aop:config> + <aop:aspect ref> + <aop:pointcut>，思想一致。

视频：P52–P60

第六节：整合篇

6.1 单元测试 JUnit

  • JUnit5：@ExtendWith(SpringExtension.class) + @ContextConfiguration("classpath:beans.xml")，或合并注解 @SpringJUnitConfig(locations = "...")，即可在测试类直接 @Autowired。
  • JUnit4：@RunWith(SpringJUnit4ClassRunner.class) + @ContextConfiguration。

视频：P61

6.2 JdbcTemplate

视频：P62–P64

6.3 声明式事务（当前进度 P65 起）

  • 场景：转账两条 update 必须同生共死；编程式（try/commit/rollback）太啰嗦 → 声明式（@Transactional 一行搞定，底层 AOP）。
  • 注解式：@EnableTransactionManagement + TransactionManager bean，方法/类上加 @Transactional；也可全注解配置类；XML 式用 <tx:advice> + <aop:config>。

隔离级别（isolation）：

级别 脏读 不可重复读 幻读
READ UNCOMMITTED 有 有 有
READ COMMITTED 无 有 有
REPEATABLE READ（MySQL 默认） 无 无 有
SERIALIZABLE 无 无 无

传播行为（propagation）：REQUIRED（默认，有就加入没有就新建）、REQUIRES_NEW（挂起当前，开新事务）、SUPPORTS/NOT_SUPPORTED/MANDATORY/NEVER/NESTED。

其他属性：readOnly 只读优化、timeout 超时回滚、rollbackFor（默认只回滚运行时异常，rollbackFor = Exception.class 全回滚）。

视频：P65–P71

6.4 资源操作 Resources

  • Resource 接口统一各类资源：ClassPathResource、FileSystemResource、UrlResource、ByteArrayResource……
  • ResourceLoader 按前缀决定类型：
前缀 示例 实现
classpath: classpath:jdbc.properties ClassPathResource
无 / file: / http: C:/a.txt FileSystemResource / UrlResource
  • ResourceLoaderAware 回调注入 loader；ApplicationContext 本身就是 ResourceLoader，getResource() 直接用。

视频：P72–P77

6.5 国际化 i18n

  • Java 层：ResourceBundle.getBundle(basename, locale) + .properties 消息文件（xxx_zh_CN.properties / xxx_en_US.properties）。
  • Spring 层：MessageSource bean（ResourceBundleMessageSource 设 basename），getMessage(code, args, locale)；MVC 里 RequestContext#getMessage。

视频：P78–P79

6.6 数据校验 Validation

  • 方式一 Validator 接口：实现 supports() + validate()（Errors.rejectValue），手动校验。
  • 方式二 Bean Validation 注解（JSR 380）：@NotNull、@NotBlank、@Min、@Email… 配合 @Validated 标 controller、@Valid 标参数，BindingResult 收错误。
  • 方式三 方法级校验：配置类 @Validated，方法参数加校验注解，抛 ConstraintViolationException。
  • 自定义校验：写注解 + ConstraintValidator<注解, 类型> 实现 isValid()（如”不能全是空白字符”）。

视频：P80–P83

6.7 提前编译 AOT

  • JIT vs AOT：JIT 运行时即时编译（启动慢、峰值高）；AOT 提前编译成机器码（启动毫秒级、内存省，适合 Serverless）。
  • Native Image：装 GraalVM + C++ 编译环境（VS/WSL），native-image -Dspring.native.verbose=true 打包，产物不依赖 JVM 直接跑；代价是构建慢、反射/动态代理需要额外配置。
  • Spring6 对 GraalVM Native Image 的支持正是”云原生”方向的关键特性。

视频：P84–P87

6.8 课程总结

P88 回顾全课主线：IoC 解耦对象创建 → 手写 IoC 悟原理 → AOP 解耦横切逻辑 → 事务/Resources/i18n/Validation 学整合 → AOT 看未来。学完它，再看 Spring Boot 就是”自动装配的 Spring”。

视频：P88
